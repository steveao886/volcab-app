# Volcab Vocabulary App — Design Doc

Date: 2026-07-24
Status: confirmed with user

## 1. Goal

A vocabulary-learning PWA hosted free on GitHub Pages, usable on both phone and desktop, with learning progress synced across devices. The initial word list is extracted from the user's Evernote export file (`Volcab.enex`, 26 notes), pulling out difficult words, with complete entries then generated by AI. The core memorization method is spaced repetition (SRS) + example sentences in context.

## 2. Overall Architecture

Two GitHub repos:

| Repo | Visibility | Contents |
|---|---|---|
| `volcab-app` | Public | App source code. GitHub Actions builds and deploys to GitHub Pages. When not logged in, only the token input page is shown, containing no user data. |
| `volcab-data` | Private | `words.json` (word list) + `progress.json` (learning progress). Readable/writable only by whoever holds the token. |

- **Auth = a GitHub fine-grained Personal Access Token**, scoped only to Contents read/write on the `volcab-data` repo. The token is stored in browser localStorage, pasted in once per device on first use.
- Pure front-end app, no server. All data reads/writes go through the GitHub Contents API.
- **Tech stack**: Vite + React + TypeScript + vite-plugin-pwa. Mobile-first responsive UI with bottom tab navigation; supports "Add to Home Screen," reviewable offline, auto-syncs once back online.
- Interface language: Chinese.
- **Visual style**: use the frontend-design skill for the UI, aiming for a distinctive, production-grade visual quality that avoids a generic templated feel.

## 3. Data Model

### 3.1 words.json (word list)

```json
{
  "version": 1,
  "words": [
    {
      "id": "abrogate",
      "headword": "abrogate",
      "phonetic": "/ˈæbrəɡeɪt/",
      "meanings": [
        { "pos": "v.", "en": "to formally revoke or repeal (a law, agreement, or practice)", "zh": "废除;废止" }
      ],
      "examples": [
        "The new CEO abrogated the remote-work policy, and half the team started job-hunting that week."
      ],
      "synonyms": ["repeal", "revoke", "annul"],
      "antonyms": ["ratify", "uphold"],
      "collocations": ["abrogate a treaty", "abrogate an agreement"],
      "relatedForms": [
        { "form": "abrogation", "pos": "n.", "zh": "废除;废止" }
      ],
      "sourceNote": "12-15",
      "addedAt": "2026-07-24"
    }
  ]
}
```

Conventions:

- `id` = the lowercase lemma form, unique. Derived forms (e.g. surreptitiously → surreptitious) are folded into a single entry, filed under the lemma.
- `examples`: 2–3 **freshly written** example sentences set in context, modern and close to present-day life and work scenes (workplace, projects, commuting, fitness, social media, travel, renting an apartment, etc.). **Do not reuse the original Evernote note text** — the notes are only used to determine the word list. Examples for polysemous words should cover the main senses.
- `sourceNote`: which note the word came from (e.g. "12-15"), used only as a provenance marker; words added manually by the user use `"manual"`.
- Phonetics are American.

### 3.2 progress.json (learning progress)

```json
{
  "version": 1,
  "settings": { "newPerDay": 10 },
  "words": {
    "abrogate": {
      "state": "review",
      "ease": 2.5,
      "intervalDays": 7,
      "due": "2026-07-30",
      "reps": 5,
      "lapses": 1,
      "lastReviewedAt": "2026-07-23T14:02:11Z"
    }
  },
  "dailyStats": {
    "2026-07-24": { "reviewed": 25, "newLearned": 10, "correct": 21, "quizTaken": 1 }
  }
}
```

- `state`: `new` (not yet studied) → `learning` (in progress, short intervals) → `review` (graduated, long intervals).
- Words present in the word list but with no record in progress are treated as `new`.
- No full review log is kept, only daily aggregated stats (`dailyStats`), to keep the file size in check.
- Streak is derived from `dailyStats`, not stored separately.

## 4. Memorization Algorithm (an SM-2 variant, Anki-style)

Each review is graded on a four-way choice: **Again / Hard / Good / Easy**.

- **New-word learning phase**: learning steps go 1 minute → 10 minutes (reappearing within the same session); "Good" graduates the word after finishing the steps, with a first review interval of 1 day and an initial ease of 2.5. "Easy" graduates it immediately, with an interval of 4 days.
- **Review phase**:
  - Again: records a lapse, returns to the learning phase, ease −0.20;
  - Hard: interval × 1.2, ease −0.15;
  - Good: interval × ease;
  - Easy: interval × ease × 1.3, ease +0.15.
- Ease floor of 1.3; interval cap of 365 days; interval gets ±5% random fuzz added, so the same batch of words doesn't always come due on the exact same day.
- **Daily queue** = all words with `due ≤ today` (given priority) + `newPerDay` new words (in word-list order).
- Words missed in a quick test have their `due` moved up to today (a light-touch linkage, ease is not changed).

## 5. Features and Pages

| Page | Function |
|---|---|
| Login | Paste in a token + a built-in illustrated guide (how to generate a fine-grained PAT); enters the app after validation |
| Today (home) | Due review count, new-word count for today, streak, overall progress bar; entry points: start review / quick test |
| Review | SRS cards: front shows the word (+ pronounce button); flip to show phonetics, Chinese/English definitions, example sentences in context, synonyms/antonyms, collocations; four-key grading |
| Quick Test | 10 random questions from studied words, three question types mixed: see word pick meaning (4 choices), see meaning pick word (4 choices), spelling (see definition + phonetics, type the word); shows a score at the end, missed words have their due date moved up |
| Word List | Full list + search (searchable by headword, English definition, or Chinese definition) + filters (mastery status / source note); tap into entry detail; supports multi-select bulk delete |
| Entry Detail | Full entry display + TTS pronunciation + edit (change definitions/examples/etc., written back to words.json) + delete entry |
| Add Word | Type a word → calls the Free Dictionary API (dictionaryapi.dev, free, no key needed) to auto-fill phonetics and English definition → user can edit and add the Chinese definition → saved; fully manual entry when the API can't find it |
| Settings | Daily new-word count, token management (change/log out), export all data as a JSON backup |

Pronunciation: Web Speech API (speechSynthesis, en-US), free, works on both mobile and desktop.

## 6. Sync Mechanism

- **Pull**: on app startup, GET `words.json` and `progress.json` (with sha caching, no re-download when unchanged).
- **Push**: debounced 30 seconds after a review session ends or data changes, committed via the Contents API PUT (with the last-known sha).
- **Conflict** (409, both devices have made changes): re-fetch the remote copy, merge per word — for each word, keep whichever record has the newer `lastReviewedAt`; for `dailyStats`, take the max of each field per day; push again after merging. No data is lost.
- **Offline**: changes are staged in localStorage, auto-syncs once network is restored; the UI shows an offline/unsynced indicator.

## 7. Initial Word-List Build (one-time pipeline)

1. A script parses `Volcab.enex` (XML + embedded ENML): extracts words/phrases marked with `<b>` in each note; only 12 of the 26 notes have bold markup (201 instances total), the other 14 are unmarked lemma-themed paragraphs that the AI must read through and judge for difficulty — bold is just one signal, difficulty is judged by the word's actual level.
2. Cleanup: strip common words out of plain phrase collocations, reduce to lemma form, dedupe across notes.
3. **Difficulty filtering (the key step)**: apply a uniform, strict difficulty bar across the merged candidate table, keeping only genuinely worth-memorizing C1+/C2 vocabulary, cutting B2-and-easier narrative filler words (things like outskirts, brisk, trivial, surplus, foster). **Target size 350–450 words**; better fewer and well-chosen — more can always be added in the app later.
4. AI batch-generates entries (phonetics, Chinese/English senses, example sentences in context, synonyms/antonyms, collocations), produced in batches and schema-validated.
5. The generated `words.json` is committed to `volcab-data`; sample a number of entries for manual quality review.
6. The `.enex` parsing script stays in the app repo under `scripts/`, for future re-imports.

## 8. Error Handling

- Invalid/expired/insufficient-permission token → clear the local token, return to login and show the reason.
- GitHub API rate limiting (5000 requests/hour once authenticated, far more than normal use would hit) → prompt to retry later.
- Sync conflicts → auto-merged (see §6), transparent to the user.
- Dictionary API failure → fall back to manual entry.
- words.json / progress.json fails to parse or doesn't match the schema → refuse to overwrite the remote copy, prompt to export a backup.

## 9. Testing

- **Unit tests (Vitest)**: the SRS scheduler (every grading path, edge cases), conflict-merge logic, the enex parser, the quiz generator (options don't repeat, distractors are reasonable), schema validation.
- **Manual acceptance**: run through the full flow once each on desktop Chrome and a mobile browser (login, review, test, search, add, offline, two-device sync).

## 10. Deployment and First-Time Setup

1. Create the two repos, `volcab-app` (public) and `volcab-data` (private).
2. Configure GitHub Actions on `volcab-app`: build and deploy to Pages on every push.
3. The user follows the in-app guide to generate a fine-grained PAT (`volcab-data` only, Contents Read/Write), pasted in once per device.

## 11. Non-Goals (explicitly out of scope)

- A multi-user system or a signup flow (single-user, personal use).
- Server-side components, a database.
- Interface languages other than Chinese; learning languages other than English.
- A full review history log or elaborate charts (daily aggregates only).
